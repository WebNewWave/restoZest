# Zest Resto — три концепта сайта

Демонстрационные концепты сайта для ресторана **Zest Resto** (Махачкала, ул. Красноярская, 5).
Собраны по материалам публичного профиля [@resto.zest](https://www.instagram.com/resto.zest),
меню ресторана и данным карт.

Ресторан: европейская и кавказская кухня, мангал на живом угле, приватные кабины,
зал под торжества. Работает ежедневно 10:00–23:00, завтраки 10:00–14:00,
средний чек 800–1500 ₽.

---

## Что внутри

```
restoZest/
├── data/
│   ├── menu.json          полное меню с ценами (167 позиций) — правится без кода
│   └── restaurant.json    контакты, часы, факты, события, палитра бренда
├── assets/
│   └── instagram/         13 кадров из профиля ресторана
├── docs/
│   ├── research.md        досье: что удалось выяснить о ресторане
│   └── concepts.md        разбор трёх концептов: замысел, палитра, отличия
├── supabase/
│   └── schema.sql         таблицы и политики для приёма заказов
├── projects/
│   ├── shared/            общая библиотека: типы, данные, корзина, заказы
│   ├── concept-espresso/  концепт 1 — тёмный премиум
│   ├── concept-lumen/     концепт 2 — светлый, меню-первым
│   └── concept-gorsky/    концепт 3 — локальная идентичность
├── angular.json
├── package.json
└── tsconfig.json
```

Три концепта живут в одном Angular-воркспейсе и делят общую библиотеку. Это одно
`node_modules` вместо трёх, общие данные меню и один сервис заказов. Собрать и
выложить каждый концепт можно отдельно: `ng build concept-espresso` даёт свою
папку в `dist/`. Если понадобится развести концепты по отдельным репозиториям —
папка каждого концепта самодостаточна, переносится вместе с `projects/shared`.

## Запуск

```bash
npm install

npm run start:espresso   # http://127.0.0.1:4201
npm run start:lumen      # http://127.0.0.1:4202
npm run start:gorsky     # http://127.0.0.1:4203

npm run build:espresso   # сборка в dist/concept-espresso
npm run build:all        # все три
```

### Адреса

Маршруты одинаковы во всех трёх концептах — различается только оформление:

| Адрес | Что там |
|---|---|
| `/` | главная: герой, о ресторане, блюда-визитки, атмосфера, торжества, QR-блок, бронь, контакты |
| `/menu` | полное меню с поиском и фильтром по категориям |
| `/menu?tag=national` | только горская кухня — 22 блюда (концепт «Горский код») |
| `/events` | торжества и банкеты: поводы, что берём на себя, заявка |
| `/t/7` | **заказ со стола** — то, что открывается по QR на столе №7 |
| `/kitchen` | **экран кухни** — сюда прилетают заказы с номером стола |

Что у каждого концепта своё:

| | «Espresso» | «Lumen» | «Горский код» |
|---|---|---|---|
| Первый экран | кадр фасада, тёмный | меню и поиск, светлый | горская кухня и мангал |
| Поиск в первом экране | нет | да, ведёт в `/menu?q=` | нет |
| Особый фильтр | — | категории-плитки | «Горская кухня» — 22 позиции |
| Экран кухни | светлый | светлый | тёмный, с меткой горских блюд |

## Заказ со стола по QR

Механика: гость сканирует QR на столе → открывается `/t/<номер стола>` → видит меню
с ценами → собирает заказ → на кухне появляется карточка с номером стола, составом,
суммой, временем и пожеланием.

Сейчас работает в двух режимах:

1. **Демо-режим (по умолчанию).** Supabase не подключён. Заказ сохраняется в браузере
   и мгновенно появляется на `/kitchen` в соседней вкладке. Годится для показа механики
   клиенту без настройки базы.
2. **Supabase.** Заказы уходят в базу и видны на кухне с любого устройства, обновление
   в реальном времени.

### Подключение Supabase

1. Создайте проект на [supabase.com](https://supabase.com).
2. Откройте SQL Editor и выполните `supabase/schema.sql` целиком.
3. Впишите в `projects/shared/src/lib/supabase.config.ts` значения `url` и `anonKey`
   из Settings → API.
4. Перезапустите сборку. Режим переключится автоматически.

QR-код лежит в `assets/qr/table-7.svg`. Пересобрать под свой адрес:

```bash
node scripts/make-qr.mjs "https://ваш-домен/t/7" assets/qr/table-7.svg
```

Для каждого стола — свой QR со своим номером. Печатается и кладётся на стол.

## Как править меню и контакты

Меню — это `data/menu.json`. Формат:

```json
{
  "categories": [
    {
      "id": "steaks",
      "name": "Стейки",
      "items": [{ "id": "s2", "name": "Стейк Томагавк", "price": 1450, "hit": true }]
    }
  ]
}
```

`hit: true` помечает блюдо как «выбор гостей» — оно подсвечивается в карточке.
`tags` (`рыба`, `вег`, `национальное`, `острое`, `морепродукты`) выводятся плашками.

Контакты, часы и список торжеств — `data/restaurant.json`. Правки в этих файлах
не требуют пересборки кода, достаточно обновить файлы на хостинге.

### Как проверялось

Каждый концепт прогонялся в настоящем браузере по одному и тому же сценарию:

1. Обход `/`, `/menu`, `/events`, `/kitchen` — снимки экрана и ошибки в консоли.
2. Сквозной заказ со стола: `/t/7` → три позиции → корзина → пожелание → отправка.
3. Экран кухни: появилась карточка «Стол №7» с тремя строками → смена статуса.
4. Мобильный вид 390×844.
5. Поиск из первого экрана (там, где он есть) — переход в меню с результатами.

Результат по всем трём: 167 кнопок в меню, корзина «3» на 1 710 ₽, заказ доходит до
кухни, статус меняется, уведомление «Заказ отправлен на кухню» показывается.
Фильтр «Горская кухня» даёт ровно 22 позиции из 167, прямая ссылка `?tag=national`
показывает те же 22 и ни одной лишней.
